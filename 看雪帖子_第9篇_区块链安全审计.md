# 区块链安全：智能合约自动化审计引擎开发

## 一、智能合约安全的特殊性

智能合约安全和传统安全完全不同：
- 代码一旦部署不可修改，漏洞就是永久的
- 一次漏洞可能损失数千万美元（The DAO、Ronin、Wormhole）
- 审计费用极高：一次专业审计$10K-$100K
- 人工审计慢：一个中等合约要1-2周

我的目标是做一个**智能合约自动化审计引擎**：输入合约代码 → 多维度扫描 → AI深度分析 → 输出审计报告。

## 三、编译与AST解析

首先用solc编译合约，生成AST（抽象语法树）：

```python
class ContractCompiler:
    def __init__(self, source_code: str, version: str = "0.8.19"):
        self.source_code = source_code
        self.version = version
    
    async def compile(self) -> CompileResult:
        # 写入临时文件
        with tempfile.NamedTemporaryFile(suffix=".sol", delete=False) as f:
            f.write(self.source_code.encode())
            sol_path = f.name
        
        # 用solc编译，生成AST和ABI
        result = await run_command([
            "solc", f"--overwrite",
            "--ast-compact-json",
            "--abi",
            "--bin",
            "-o", tempfile.mkdtemp(),
            sol_path
        ])
        
        return CompileResult(
            ast=parse_ast(result.ast_json),
            abi=json.loads(result.abi),
            bytecode=result.bin,
            errors=result.errors
        )
```

## 四、静态分析：常见漏洞模式

### 4.1 重入攻击检测

重入攻击是最经典的智能合约漏洞。检测模式：

```python
def detect_reentrancy(ast: ASTNode) -> list[Vulnerability]:
    vulns = []
    
    # 查找所有外部调用（call/send/transfer）
    external_calls = ast.find_all(
        node_type="FunctionCall",
        filter=lambda n: is_external_call(n)
    )
    
    for call in external_calls:
        # 检查调用后是否有状态变更
        function = call.find_ancestor("FunctionDefinition")
        state_changes_after = function.find_state_changes_after(call)
        
        if state_changes_after:
            vulns.append(Vulnerability(
                type="reentrancy",
                severity="high",
                function=function.name,
                line=call.line,
                description=f"函数{function.name}中存在重入风险：外部调用后有状态变更",
                suggestion="使用checks-effects-interactions模式，或使用ReentrancyGuard"
            ))
    
    return vulns
```

### 4.2 整数溢出检测

```python
def detect_integer_overflow(ast: ASTNode, solc_version: str) -> list[Vulnerability]:
    vulns = []
    
    # Solidity 0.8.0+内置溢出检查，低版本才需要检测
    if version_gte(solc_version, "0.8.0"):
        return vulns
    
    # 查找算术运算
    arithmetic_ops = ast.find_all(
        node_type="BinaryOperation",
        filter=lambda n: n.operator in ["+", "-", "*"]
    )
    
    for op in arithmetic_ops:
        # 检查是否有SafeMath保护
        if not has_safemath_protection(op):
            vulns.append(Vulnerability(
                type="integer_overflow",
                severity="medium",
                line=op.line,
                description=f"整数运算可能溢出：{op.expression}",
                suggestion="升级到Solidity 0.8.0+，或使用SafeMath库"
            ))
    
    return vulns
```

### 4.3 权限检查缺失

```python
def detect_access_control(ast: ASTNode) -> list[Vulnerability]:
    vulns = []
    
    # 查找状态变更函数
    state_changing_funcs = ast.find_all(
        node_type="FunctionDefinition",
        filter=lambda n: n.is_state_changing() and n.visibility in ["public", "external"]
    )
    
    for func in state_changing_funcs:
        # 检查是否有权限修饰符
        has_modifier = any(
            m in ["onlyOwner", "onlyAdmin", "requiresAuth"]
            for m in func.modifiers
        )
        has_require = any(
            "msg.sender" in r.expression
            for r in func.find_requires()
        )
        
        if not has_modifier and not has_require:
            vulns.append(Vulnerability(
                type="access_control",
                severity="high",
                function=func.name,
                line=func.line,
                description=f"函数{func.name}可修改状态但缺少权限检查",
                suggestion="添加onlyOwner修饰符或require(msg.sender == owner)"
            ))
    
    return vulns
```

## 五、集成Slither和Mythril

自研规则覆盖常见漏洞，但复杂漏洞需要专业工具：

```python
async def run_slither(contract_path: str) -> list[Vulnerability]:
    result = await run_command([
        "slither", contract_path,
        "--json", "-",
        "--exclude-optimization",
        "--exclude-informational"
    ], timeout=120)
    
    return parse_slither_result(result.json_output)

async def run_mythril(contract_path: str) -> list[Vulnerability]:
    result = await run_command([
        "myth", "analyze", contract_path,
        "--solv", "0.8.19",
        "-t", "3",  # 交易深度
        "--execution-timeout", "120"
    ], timeout=300)
    
    return parse_mythril_result(result)
```

## 六、AI业务逻辑分析

工具只能扫已知漏洞模式，**业务逻辑漏洞**需要AI分析：

```python
async def ai_business_logic_audit(
    contract_code: str,
    static_vulns: list[Vulnerability],
    contract_info: ContractInfo
) -> list[Vulnerability]:
    prompt = f"""
    你是一个智能合约安全审计专家。分析以下合约的业务逻辑漏洞。
    
    合约名称：{contract_info.name}
    合约功能：{contract_info.description}
    
    已发现的技术漏洞：
    {json.dumps([v.to_dict() for v in static_vulns], ensure_ascii=False)}
    
    合约代码：
    ```solidity
    {contract_code}
    ```
    
    重点分析：
    1. 业务逻辑是否有漏洞（如价格操纵、闪电贷攻击、治理攻击）
    2. 经济模型是否合理（如通胀、通缩、奖励分配）
    3. 升级机制是否安全（如代理合约、权限管理）
    4. 与其他合约的交互是否有风险
    
    输出格式：JSON数组，每个元素包含type/severity/description/suggestion
    """
    
    result = await ai_chat(prompt)
    return parse_ai_vulns(result)
```
