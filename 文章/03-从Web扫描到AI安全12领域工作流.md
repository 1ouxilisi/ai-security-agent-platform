## 渗透测试不是跑个nmap就完了

很多人对渗透测试的理解停留在：开个终端，nmap扫一下，找到个开放端口，完事。

真正的渗透测试是一个完整的工作流：
1. **信息收集**：域名→子域名→IP→端口→服务
2. **漏洞发现**：对应服务找漏洞
3. **漏洞验证**：手动确认不是误报
4. **后渗透**：拿到权限后横向移动
5. **报告**：写清楚发现、影响、修复建议

这个过程涉及Web、内网、云、移动等多个领域。我把这些串成了一个自动化工作流。

## 完整工作流

### 阶段一：资产发现

输入一个域名，先搞清楚目标到底有什么：

```
example.com
  ├── subfinder → 子域名
  │     ├── api.example.com
  │     ├── test.example.com
  │     └── dev.example.com
  ├── nmap → IP:端口
  │     ├── 80/tcp  http
  │     ├── 443/tcp https
  │     ├── 8080/tcp http-proxy
  │     └── 22/tcp  ssh
  └── httpx → Web服务标题/技术栈
        ├── example.com → Nginx/1.20
        └── api.example.com → Spring Boot
```

这一步输出一张资产清单。很多漏洞不在主站，在test.example.com这种测试环境里——因为开发人员忘了关。

### 阶段二：漏洞扫描

有了资产清单，对应每个服务自动选模板：

| 端口/服务 | 扫描工具 | 检测内容 |
|-----------|----------|----------|
| 80/443 | nuclei | Web漏洞、暴露面板、错误配置 |
| 22 | nmap脚本 | SSH弱密码、旧版本CVE |
| 8080 | nuclei | 默认凭证、Actuator暴露 |
| 数据库端口 | nmap脚本 | 未授权访问 |

nuclei加载13742个模板，覆盖CVE、CWE、暴露面板、默认凭证、混淆内容。

### 阶段三：AI分析

扫描结果是一堆机器输出，人看头疼。把结果发给大模型：

```
目标example.com的扫描结果:
- 开放端口: 80,443,8080,22
- 子域名: api,test,dev
- nuclei发现: /actuator/health暴露
- 技术栈: Nginx + Spring Boot

请给出:
1. 风险评估（高/中/低）
2. 每个发现的修复建议
3. 下一步测试方向
```

AI返回中文报告，直接导出HTML/PDF给客户。

## MITRE ATT&CK实战

不是为了用框架而用框架。每个阶段对应ATT&CK战术：

| 阶段 | ATT&CK战术 | 实际动作 |
|------|-----------|----------|
| 信息收集 | TA0043 侦察 | subfinder/OSINT |
| 找入口 | TA0001 初始访问 | 漏洞利用/钓鱼 |
| 执行代码 | TA0002 执行 | webshell/反向shell |
| 持久化 | TA0003 持久化 | 后门/计划任务 |
| 提权 | TA0004 权限提升 | 漏洞提价/配置错误 |
| 防御规避 | TA0005 | 清除日志/加密通信 |
| 凭证访问 | TA0006 | 哈希抓取/键盘记录 |
| 发现 | TA0007 | 内网扫描/域枚举 |
| 横向移动 | TA0008 | SMB/WMI/PtH |
| 收集 | TA0009 | 文件搜索/数据库 |
| 命令控制 | TA0011 | C2通道/域名前置 |
| 数据 exfil | TA0010 | 数据压缩/加密外发 |

报告里每个发现都标注ATT&CK战术ID，客户一看就知道这是什么级别的风险。

## 靶场怎么练

光看理论不行。4个合法靶场：

```bash
# DVWA: 最基础的SQL注入/XSS
docker run -d -p 8080:80 vulnerables/web-dvwa

# Juice Shop: 现代SPA漏洞，有难度
docker run -d -p 3000:3000 bkimminich/juice-shop

# WebGoat: OWASP官方教学
docker run -d -p 8081:8080 webgoat/webgoat

# VAmPI: 专门测API安全
docker run -d -p 5000:5000 ehess/vampi
```

靶场跑起来后，在平台输入localhost:8080走一遍完整流程，你就能看到：
- 资产发现阶段找到什么
- 漏洞扫描报什么
- AI报告怎么写
