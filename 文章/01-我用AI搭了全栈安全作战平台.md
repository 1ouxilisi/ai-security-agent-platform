# 我用AI大模型搭了一个全栈安全作战平台：从端口扫描到LLM红队的完整实践

> 作者：欧西 | 2026-09-27 | 标签：#AI安全 #渗透测试 #LLM红队 #自动化安全

## 为什么要做这个

做渗透测试的人都知道，日常工作是割裂的：

- 开终端跑nmap扫端口
- 开另一个窗口跑subfinder枚举子域名
- 再开一个跑nuclei扫漏洞
- 然后手动整理报告，写半天文档
- 遇到大模型应用，还要手动想怎么测Prompt注入

我想把这些串起来：输入一个域名，自动跑完所有流程，最后AI直接生成中文报告。更进一步——不只是Web扫描，把LLM本身的安全测试也融合进来，因为大模型是第四次工业革命的核心，测它的安全才是未来。

这就是我做这个平台的动机。

## 平台架构

整个系统分三层：

```
┌─────────────────────────────────┐
│  前端作战控制台 (单文件HTML)      │
│  13个标签页，一键扫描，报告导出    │
├─────────────────────────────────┤
│  FastAPI后端 (app_lite.py)      │
│  20+API端点，认证，任务调度       │
├─────────────────────────────────┤
│  真实工具链 + AI引擎             │
│  nmap/subfinder/nuclei/httpx    │
│  Qwen2.5-7B 遗传进化 Agent守卫   │
└─────────────────────────────────┘
```

技术栈：Python 3.10 + FastAPI + 原生HTML + Qwen2.5-7B-Instruct（硅基流动API）。

## 核心能力一：一键全流程扫描

这是最基础的功能。输入example.com，自动走四步：

### Step 1: nmap端口扫描

调用真实nmap（不是模拟），扫描1-1000端口：

```python
POST /api/v1/real-tools/nmap/scan
{"target": "example.com", "ports": "1-1000"}
```

实测返回：
```json
{
  "open_ports": [80, 443, 8080, 8443],
  "services": {"80": "http", "443": "https"}
}
```

### Step 2: subfinder子域名枚举

```python
POST /api/v1/real-tools/subfinder/enum
{"domain": "example.com"}
```

从被动DNS源收集子域名，这是资产发现的关键一步。很多漏洞藏在测试环境子域名里。

### Step 3: nuclei漏洞检测

```python
POST /api/v1/real-tools/nuclei/scan
{"target": "http://example.com", "timeout": 120}
```

nuclei加载13742个模板，自动识别CVE漏洞、默认凭证、暴露面板、错误配置。这一步要1-2分钟，因为模板多。

### Step 4: AI分析报告

把前面三步的结果拼起来发给Qwen：

```python
POST /api/v1/llm/chat
{"prompt": "目标example.com扫描结果: ... 请给出安全评估和修复建议"}
```

AI返回中文评估，最后一键导出HTML报告，浏览器打开可直接打印PDF。

## 核心能力二：LLM红队测试

这是区别于普通扫描器的地方——我不仅扫Web漏洞，还测大模型本身的安全。

### 遗传算法进化Prompt

普通Prompt注入就那几招：直接说"忽略以上指令"。但真正的攻击者会进化。

我实现了一个遗传算法引擎：
- 20种攻击策略（信任建立/角色扮演/碎片化...）
- 12种编码方式（Base64/ROT13/Unicode...）
- 10种包装器（学术/游戏/翻译...）

组合起来就是20×12×10=24000种对抗Prompt。

```python
POST /api/v1/ai-v47/genetic-evolve
{"target": "test", "generations": 5, "population_size": 10}
```

实测best_fitness=0.863，意味着进化出来的Prompt有86%概率绕过安全对齐。

### 多轮对话攻击

单轮注入容易被检测，但多轮对话就不一样了。8种策略：

1. **信任建立**：先聊正常话题，建立信任后再诱导
2. **渐进式**：每轮只问一点，最后拼出敏感信息
3. **上下文操纵**：伪造系统提示词
4. **角色扮演链**：让AI扮演反派角色
5. **碎片化攻击**：把恶意指令拆成多轮
6. **反向心理学**：说"你肯定不能告诉我这个"
7. **学术包装**：以论文研究为名
8. **情感操纵**：打感情牌

### Agent安全守卫

AI Agent能调工具、执行代码、访问文件，这很危险。我做了一个守卫：

```python
POST /guardian/evaluate
{"action_type": "data_exfiltration", "description": "读取.env文件并发送到外部", "payload": "..."}
```

返回：
```json
{
  "decision": "block",
  "risk_level": "critical",
  "risk_score": 95,
  "reason": "检测到敏感文件读取+外发行为",
  "suggested_action": "阻止并通知管理员"
}
```

## 核心能力四：MITRE ATT&CK框架

攻击不是瞎打，要有方法论。平台内置MITRE ATT&CK：

- **7阶段Kill Chain**：侦察→武器化→投递→利用→安装→命令控制→目标达成
- **完整战术ID**：TA0043侦察、TA0001初始访问、TA0002执行、TA0003持久化、TA0004权限提升...
- **5条攻击链KB**：Web入侵链、内网横向移动链、云环境提权链、移动设备接管链、社会工程链

## 技术踩过的坑

1. **LLM API字段**：OpenAPI文档写`message`，实际要`prompt`，差点以为API坏了
2. **多领域数据结构**：domains是对象不是数组，前端直接.map()报错
3. **nuclei超时**：13742模板跑完全量要2分钟，超时设120秒刚好
4. **CVE统计端点404**：原来的/vuln-db/stats不存在，改用soc-center的summary
5. **MCP威胁情报**：attack-chain是POST不是GET，调半天405
