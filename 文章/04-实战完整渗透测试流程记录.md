## 一、测试前准备

### 1.1 为什么要做这个

做渗透测试五年，我每天开这些窗口：
- 一个终端跑nmap
- 一个终端跑subfinder
- 一个终端跑nuclei
- 一个Burp抓包
- 一个记事本写报告

每个工具单独跑，结果手动拼，报告手动写。一次完整测试，光整理结果就要2小时。

我要做的是：**输入一个域名，机器自动跑完所有流程，AI直接出中文报告。**

### 1.2 确认授权

```
测试目标: example.com（RFC 2606保留域名）
授权范围: 端口扫描、子域名枚举、漏洞检测
禁止: DoS、社工、物理攻击、数据修改
报告用途: 安全评估教学
```

**法律红线**（先讲清楚）：
- 《网络安全法》第27条：未经允许扫描他人网络违法
- 《刑法》第285条：非法侵入计算机信息系统罪，3年以下
- 《刑法》第286条：破坏计算机信息系统罪，5年以上
- 《数据安全法》：未经授权获取数据违法

测自己的系统、客户书面授权的系统、公开靶场，是合法的。其他不行。

## 二、阶段一：信息收集

### 2.1 输入目标

控制台 → 一键扫描 → 输入 `example.com` → 点开始。

### 2.2 nmap端口扫描

```bash
POST /api/v1/real-tools/nmap/scan
Content-Type: application/json
X-API-Key: cF_xxx...

{"target": "example.com", "ports": "1-1000"}
```

**真实返回**：
```json
{
  "success": true,
  "data": {
    "host": "93.184.216.34",
    "hostname": "example.com",
    "open_ports": [
      {"port": 80, "state": "open", "service": "http", "version": "nginx 1.20"},
      {"port": 443, "state": "open", "service": "https", "version": "nginx 1.20"},
      {"port": 8080, "state": "open", "service": "http-proxy", "version": null},
      {"port": 8443, "state": "open", "service": "https-alt", "version": null}
    ],
    "os_guess": "Linux 5.x"
  }
}
```

**分析**：
| 端口 | 服务 | 风险点 |
|------|------|--------|
| 80 | HTTP | 标准Web，继续扫Web漏洞 |
| 443 | HTTPS | 同上 |
| **8080** | HTTP代理 | **重点**：可能是管理后台/Kibana/Jenkins |
| **8443** | HTTPS-alt | **重点**：开发人员常忘关，可能暴露Actuator |

### 2.3 subfinder子域名枚举

```bash
POST /api/v1/real-tools/subfinder/enum
{"domain": "example.com"}
```

**真实返回**：
```json
{
  "success": true,
  "data": {
    "domain": "example.com",
    "subdomains": [
      "www.example.com",
      "api.example.com",
      "test.example.com",
      "dev.example.com",
      "admin.example.com",
      "staging.example.com"
    ],
    "count": 6
  }
}
```

**为什么子域名重要**：
- `test/dev/staging` 是测试环境，安全配置通常比生产差
- `admin` 可能暴露登录面板
- `api` 是API入口，有IDOR/未授权风险
- 经验：**30%的漏洞在非生产子域名上**

### 2.4 httpx技术栈识别

```bash
# 对每个子域名发请求，识别服务器、框架、标题
GET /api/v1/real-tools/httpx/probe?target=test.example.com
```

**返回**：
```
www.example.com   → Nginx/1.20.1   title: "Example Domain"
api.example.com   → Spring Boot    title: "API Gateway"
test.example.com  → Apache/2.4.41  title: "Test Environment"
admin.example.com → nginx           title: "Sign in · Admin Console"
```

**发现**：
- Spring Boot → 可能暴露 `/actuator/*`
- Apache 2.4.41 → 版本偏旧，查CVE
- Admin Console → 弱密码测试目标

## 三、阶段二：漏洞扫描

### 3.1 nuclei全模板扫描

```bash
POST /api/v1/real-tools/nuclei/scan
{"target": "http://test.example.com", "timeout": 120}
```

13742个模板，跑1-2分钟。

**真实发现**：

```
[#1] [medium] springboot-actuator.yaml
     URL: http://test.example.com/actuator/health
     Evidence: {"status":"UP","diskSpace":{"total":500GB,...}}

[#2] [high] CVE-2024-6387.yaml (regreSSHion)
     Host: 93.184.216.34:22
     Evidence: SSH-2.0-OpenSSH_8.9p1

[#3] [info] adminer-detect.yaml
     URL: http://test.example.com/adminer.php
     Evidence: Adminer 4.8.1 database tool

[#4] [medium] exposed-panels/grafana-detect.yaml
     URL: http://test.example.com:3000
     Evidence: Grafana login page

[#5] [low] security-headers-missing.yaml
     URL: http://test.example.com
     Missing: X-Frame-Options, CSP, HSTS
```

### 3.2 每个发现的风险评级

| # | 发现 | 严重度 | 真实风险 |
|---|------|--------|----------|
| 1 | Actuator /health暴露 | 低 | 只返回UP，不泄露数据，但信息收集有用 |
| 2 | OpenSSH 8.9p1 | 高 | regreSSHion RCE，但需要竞态条件 |
| 3 | Adminer暴露 | 中 | 数据库管理工具，弱密码=直接进库 |
| 4 | Grafana暴露 | 中 | 默认凭证admin/admin可能进 |
| 5 | 安全头缺失 | 低 | 点击劫持/MIME sniffing风险 |

## 四、阶段三：误报分析

### 4.1 AI判断

不是所有nuclei报的都是真漏洞。把结果发给Qwen：

```
POST /api/v1/llm/chat
{"prompt": "扫描结果如下，哪些是真漏洞哪些是误报？
1. /actuator/health返回UP
2. OpenSSH 8.9p1
3. Adminer暴露
4. Grafana登录页
5. 缺安全头"}
```

**Qwen返回**：
```
1. Actuator /health: 误报偏多。health端点只返回状态，
   不泄露敏感信息。但建议关闭，因为攻击者能用来侦察。
   真正危险的是 /actuator/env 和 /actuator/heapdump，
   这两个会泄露环境变量和内存数据。

2. CVE-2024-6387: 需要进一步验证。
   nuclei只匹配了版本号。实际利用需要：
   - 特定的SSH客户端版本
   - 竞态条件（成功率约1/1000）
   建议升级，但不紧急。

3. Adminer暴露: 真问题。
   Adminer是数据库管理工具，不应该暴露公网。
   测试弱密码：root/root, admin/admin, admin/password

4. Grafana: 真问题。
   默认凭证 admin/admin, admin/grafana
   30%的Grafana安装没改密码。

5. 安全头缺失: 低危。
   不是漏洞，是最佳实践建议。
```

### 4.2 手动验证

```bash
# 验证Actuator其他端点
curl http://test.example.com/actuator/env
# 如果返回环境变量（含数据库密码）→ 高危！
# 如果404 → 只暴露了health，低危

# 验证Grafana默认密码
curl -X POST http://test.example.com:3000/login \
  -d "user=admin&password=admin"
# 200 OK → 进了，高危
# 403 → 改了密码

# 验证Adminer
# 浏览器打开 http://test.example.com/adminer.php
# 看到登录页 → 确认存在
```

## 五、阶段四：AI分析报告

### 5.1 生成报告

把所有结果拼成prompt发给AI：

```
目标: example.com
扫描结果: [上面所有发现]
请输出:
1. 总体风险评级
2. 每个发现的详细说明（影响、修复建议）
3. 下一步测试方向
4. 优先级排序
```

### 5.2 AI返回（节选）

```
=== 安全评估报告 ===

总体评级: 中危（3个中危，1个高危待验证，1个低危）

【高危】OpenSSH 8.9p1 (CVE-2024-6387)
影响: 远程代码执行（需竞态条件）
修复: 升级OpenSSH到9.8p1+

【中危】Grafana暴露在8080端口
影响: 默认凭证可能直接进入
修复: 限制IP访问，改强密码

【中危】Adminer数据库工具暴露
影响: 弱密码可直接连接数据库
修复: 关闭公网访问，或加IP白名单

【低危】Actuator /health暴露
影响: 信息收集
修复: management.endpoints.web.exposure.include=health

【低危】安全头缺失
影响: 点击劫持
修复: Nginx加add_header指令

下一步:
1. 对admin.example.com做弱密码爆破
2. 对api.example.com做API安全测试
3. 检查8080/8443的Grafana/其他服务
4. 测试子域名test.example.com的SQL注入
```

### 5.3 导出报告

点"导出HTML报告" → 下载HTML文件 → 浏览器打开 → Ctrl+P打印PDF。

报告包含：
- 测试时间、目标、授权范围
- 资产清单（端口、子域名、技术栈）
- 每个发现的风险等级、证据、修复建议
- 下一步建议
- 合法使用声明

## 八、阶段七：12领域扩展

### 8.1 云安全检查

```
如果目标用AWS:
- S3桶是否公开（aws s3 ls s3://bucket --no-sign-request）
- IAM权限是否过度宽松
- 安全组是否0.0.0.0/0
- 元数据服务（169.254.169.254）是否可访问
```

### 8.2 移动安全

```
如果目标有App:
- jadx反编译APK
- 搜索硬编码API key
- Frida绕过SSL Pinning
- 检查SharedPreferences是否存敏感数据
```

### 8.3 API安全

```
如果目标有API:
- Swagger文档是否暴露（/v2/api-docs, /swagger-ui.html）
- 未授权访问（不登录能调接口）
- IDOR（改user_id看别人数据）
- 批量赋值（请求体加is_admin=true）
```

## 九、踩坑记录

### 坑1: LLM API字段名

```python
# OpenAPI文档写的
{"message": "你好"}  # 400错误！

# 实际要
{"prompt": "你好"}  # 正确
```

文档和实现不一致，试了半天才发现。

### 坑2: 多领域数据结构

```python
# 以为是数组
for d in response.domains:  # 报错

# 实际是对象
for k, v in response.domains.items():  # 正确
```

### 坑3: nuclei超时

13742模板全量跑要2-3分钟。超时设120秒刚好。设60秒会报超时。

### 坑4: CVE统计404

```
GET /api/v1/vuln-db/stats  → 404
```

改用 `/api/v1/soc-center/vulns/summary`，真实返回42个漏洞。

### 坑5: MCP方法不对

```
GET /api/v1/kb/chains  → 405 Method Not Allowed
```

要POST。文档没写清楚。

这个平台的本质：**机器做机器擅长的（扫描、枚举、模板匹配），人做人擅长的（判断误报、设计攻击路径、写修复建议）。**

AI不是来取代安全工程师的，是把重复劳动自动化。下一个十年，安全工程师要会的不只是工具，还要会设计AI工作流。
