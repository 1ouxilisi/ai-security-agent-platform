# 我用AI做了一个自动化渗透测试平台，65万行代码，开源了

> 个人开发者，用AI Agent造了个能自动扫漏洞出报告的安全测试平台，开源了。

---

## 一、为什么做这个

我是一个独立开发者，平时做安全测试的时候发现一个问题：

**80%的工作都是重复性的。**

信息收集、端口扫描、服务识别、漏洞匹配、出报告……这些工作占了大部分时间，但技术含量不高，谁都能做。

真正有价值的是那20%：深度漏洞分析、复杂业务逻辑漏洞、0day挖掘、内网横向移动。

我就想，能不能用AI把那80%的重复性工作自动化，让安全工程师只专注20%的深度分析？

于是就有了这个项目。

---

## 二、这个平台能做什么

简单说，**输入一个目标（域名/IP/网址），它能自动完成从信息收集到报告生成的全流程。**

### 1. 信息收集

- 端口扫描（哪些端口开了，跑的什么服务）
- 服务版本识别（Apache/Nginx/MySQL什么版本）
- 子域名枚举（有哪些子域名）
- 目录爆破（网站有哪些隐藏目录/页面）
- Whois信息（域名注册人、注册商、注册时间）
- DNS记录（A/CNAME/MX/TXT记录）
- SSL证书检查（证书是否过期、加密强度）
- HTTP头检查（安全头是否配置）

### 2. 漏洞扫描

- **106个CVE漏洞知识库**，智能匹配（扫描到Apache Log4j版本，自动匹配CVE-2021-44228）
- Nuclei模板扫描（集成了nuclei引擎，几千个漏洞模板）
- Web漏洞扫描（SQL注入/XSS/SSRF/文件上传/命令执行等）
- 漏洞风险评级（critical/high/medium/low）

### 3. POC验证

- **54个POC利用脚本**，发现漏洞后自动验证是否可利用
- 覆盖RCE/SQL注入/XSS/SSRF/文件上传/未授权访问等
- 验证结果自动记录，可复现

### 4. AI智能分析

这是核心，不是简单的工具调用。

- **4个专业智能体协作**：侦察智能体、利用智能体、验证智能体、报告智能体
- **ReAct推理引擎**：AI自主思考→调用工具→分析结果→下一步行动，循环直到完成任务
- **RAG检索增强**：从106个CVE知识库和54个POC库检索准确信息，不是瞎编
- 你说"帮我看看这个网站有什么安全问题"，AI自动规划任务、调用工具、分析结果、给出结论

### 5. 报告生成

- 一键生成**HTML/PDF/Markdown**专业报告
- 包含：漏洞详情、风险评级、修复建议、证据截图
- 不用手动写几十页Word了

## 三、技术架构

整个项目**65万行代码**，Python写的。

| 层级 | 技术 |
|------|------|
| 后端 | FastAPI + SQLite + Uvicorn |
| AI层 | ReAct推理引擎 + RAG检索增强 + 多智能体协作 |
| 安全工具 | Nmap、Nuclei、自定义扫描器、POC库 |
| 前端 | Streamlit + Swagger UI |
| 其他 | MCP服务器、插件系统、用户认证、告警通知、数据备份 |

核心是AI Agent层。AI会自主思考：

> "这个目标跑的是Apache 2.4.49，我应该匹配CVE-2021-41773，然后用POC验证，最后生成报告。"

不是你点一个按钮它扫一下，是你给个目标，它自己规划整个流程。

## 五、效果如何

**说实话，没有网上吹的那么神。**

### 能做好的

- 信息收集和漏洞扫描，比人工快10倍
- 常规漏洞检测，准确率还可以
- 报告生成，省了大量时间
- 重复性工作，自动化得很好

### 做不好的

- 0day漏洞，发现不了
- 复杂的业务逻辑漏洞，AI理解不了
- 深度的内网渗透，还是得人工
- 绕过WAF/IPS，AI还不够聪明
- 社会工程学，完全做不了

**所以这个平台的定位是：辅助安全工程师，不是替代安全工程师。**

它帮你完成80%的重复性工作，你专注20%的深度分析。

## 六、为什么开源

说实话，一开始没想开源，想做成SaaS卖钱。

但后来发现：

1. **个人开发者做安全SaaS，很难拿到客户**，企业不信任个人
2. **安全测试市场不大**，个人能吃到的蛋糕有限
3. 这个项目更适合当**个人品牌和作品集**，而不是直接卖钱
4. **开源了能积累star，建立个人品牌**，以后有人找你做咨询/培训/定制，反而更赚钱

所以就开源了。
